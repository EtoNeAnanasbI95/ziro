# ТЗ: ziro — автокомплит в стиле Kiro для zsh на Rust

Дата: 2026-11-13. Платформа: Linux (основная среда — Hyprland + kitty, но рендер от композитора не зависит).

## 1. Идея

**ziro** (Zsh + Kiro) — выпадающее меню подсказок прямо в терминале во время набора, как было в Kiro/Fig, плюс серый ghost-text продолжения команды.

Отличия от аналогов:
- **Kiro/Fig** рисовал меню отдельным GUI-окном через PTY-прокси. На Linux работал плохо, на Hyprland не работал, в Kiro CLI 3.0 автокомплит удалён.
- **inshellisense** — PTY-обёртка со своей базой спек. Не видит zsh: пользовательские `compdef`, completion-функции oh-my-zsh, алиасы, функции, `zstyle`.

ziro берёт UX Kiro, а **источник правды — сам zsh** (compsys + история). Рисует средствами ZLE, без GUI-окна и без PTY-прокси.

GUI-попап (через `input-method-v2` на Wayland, чтобы работал в любом терминале, включая Zed) рассматривался и отложен: много неизвестных. Архитектура должна позволить добавить его позже как второй рендерер.

Имена: бинарь `ziro`, плагин `ziro.plugin.zsh`, конфиг `~/.config/ziro/config.toml`.

## 2. Цели и ограничения

Цели:
1. Меню появляется по мере набора, без Tab.
2. Кандидаты — из штатного compsys: то же, что дал бы Tab, с описаниями, группами, пользовательскими функциями и `zstyle`.
3. Подмешивается история (с учётом cwd, частоты, свежести, кода выхода).
4. Ghost-text из истории.
5. Красивый вид: рамка, подсветка выбранного и совпавших символов, колонка описаний, иконка типа.
6. Работает в любом нормальном терминале и в tmux.

Жёсткие ограничения (нарушение = блокирующий баг):
1. **Набор не лагает.** Никакой путь на нажатие клавиши не ждёт демона, воркер, диск или внешний процесс.
2. **Не ломать oh-my-zsh и плагины**: `git`, `zsh-syntax-highlighting`, `fast-syntax-highlighting`, ↑/↓ = `up/down-line-or-beginning-search`, vi-mode. Клавиши ziro перехватываются **только когда меню видно**, иначе вызывается прежний виджет.
3. Демон упал/не запущен — шелл работает как без ziro.
4. Никакого мусора в терминале: остатков меню после Enter/Ctrl+C, сдвинутого промпта, текста меню в выполненной команде.
5. В историю ziro не попадает то, что zsh не записал бы (`HIST_IGNORE_SPACE`, `HISTORY_IGNORE`).

Не в MVP: bash/fish, свои спеки как основной источник, GUI-окно, AI, превью.

## 3. Сценарии

1. `git ch` → меню `checkout — Switch branches…`, `cherry-pick — …`. ↓, Tab → `git checkout `, сразу меню с ветками.
2. `tar -` → опции с описаниями; ввод `x` нечётко фильтрует.
3. Своя функция `deploy` с `compdef _deploy deploy` (в т.ч. объявленная в текущей сессии) → ziro предлагает её аргументы.
4. `cd ~/De` → `Desktop/`, `Development/` с учётом текущих `zstyle`.
5. `docker compose -f` → серым `docker compose -f infra/dev.yml up -d` (часто и успешно в этом каталоге). → принимает целиком, Ctrl+→ — по слову.
6. Пустая строка + ↑ → обычная история. Esc закрывает меню до следующей правки. Enter без явного выбора выполняет команду.
7. `kill -9` демона → набор продолжается, меню нет, на следующем промпте демон перезапущен.

## 4. UX

### 4.1. Когда показывается меню

Показывается после изменения буфера, если есть кандидаты. Для первого слова нужен минимум 1 символ, для аргументов — 0 (после пробела сразу подкоманды/опции).

Не показывается:
- пустой буфер;
- буфер только что изменён навигацией по истории (до следующей правки руками — чтобы повторный ↑ листал историю);
- текущее слово содержит `*`, `?`, `[` (Tab уходит прежнему виджету для раскрытия глоба);
- keymap `vicmd`;
- единственный кандидат совпадает со словом.

Скрывается: Esc, Ctrl+C, Enter, нет кандидатов.

### 4.2. Клавиши

| Клавиша | Меню видно | Меню не видно |
|---|---|---|
| ↑ / ↓, Shift+Tab | выбор | прежний виджет |
| Tab | вставить выбранный (по умолчанию первый) | прежний виджет |
| Enter | вставить, если пользователь сам двигал выбор; иначе выполнить команду | прежний виджет |
| Esc | скрыть до следующей правки (в vi-mode затем прежний виджет) | прежний виджет |
| → / End | принять ghost-text (курсор в конце) | прежний виджет |
| Ctrl+→ | принять ghost-text по слову | прежний виджет |
| PgUp / PgDn | листать меню | прежний виджет |

Режим `keys.arrows`: `menu` (по умолчанию, как Kiro) или `explicit` (меню пассивное, ↑/↓/Tab как раньше, вход в меню по Ctrl+Space).

### 4.3. Вид

```
$ git ch█
  ╭──────────────────────────────────────────────────────╮
  │ ⎇ checkout       Switch branches or restore files     │
  │   cherry-pick    Apply changes introduced by commits  │
  │ ↺ git checkout -b feat/ziro            history · 12×  │
  ╰──────────────────────────────────────────── 3/17 ────╯
```

- Под строкой ввода, выровнено по началу текущего слова, сдвигается влево, если не влезает.
- До 8 строк, счётчик `n/total`. Никогда не шире `COLUMNS` (перенос ломает подсчёт строк ZLE), описания обрезаются `…`.
- Цвета — 16 ANSI (наследуют тему терминала). Иконки — одиночные Unicode-символы, Nerd Font — опция.
- Ghost-text — серым (`fg=8`) после конца буфера.

## 5. Архитектура

```
 терминал ── zsh
              │  ziro.plugin.zsh: виджеты, хуки, рендер через POSTDISPLAY
              │
              ├─ zpty-воркер: форк текущего zsh, гоняет compsys
              │   и перехватывает compadd
              │
              └─ unix socket ──► ziro daemon (Rust, один на пользователя)
                                   ├─ сессии (по одной на шелл)
                                   ├─ история (SQLite) + импорт $HISTFILE
                                   ├─ ранжирование (nucleo-matcher)
                                   └─ раскладка меню → готовый кадр
```

Разделение ответственности: zsh знает контекст и рисует, Rust думает. Всё тяжёлое (fuzzy, frecency по 100k истории, раскладка с шириной символов, вычисление вставки) — в демоне.

### 5.1. Рендер

`POSTDISPLAY` (текст после буфера, не входит в команду) + `region_highlight` (цвета, свои записи помечаются `memo=ziro` на zsh ≥ 5.9). ZLE сам делает diff-перерисовку, скролл и очистку — без мерцания. Так работают zsh-autosuggestions и zsh-autocomplete.

`POSTDISPLAY` = ghost-text + `\n` + строки меню. Меню всегда ниже строки ввода; у нижнего края экран прокручивается.

Ширину символов демон считает через `unicode-width`; эмодзи в описаниях заменяются.

### 5.2. Конфликт с zsh-autosuggestions

Он тоже владеет `POSTDISPLAY` и при принятии делает `BUFFER+=$POSTDISPLAY` — меню попало бы в команду. Поэтому ziro сам делает ghost-text, а если autosuggestions загружен — вызывает `_zsh_autosuggest_disable` и переопределяет его accept-виджеты на свои (принимается только ghost-часть). Поддерживаем 0.7.x. `ziro doctor` советует убрать его из `plugins=()`.

### 5.3. Захват кандидатов compsys

Внутри completion-виджета объявляется функция `compadd`, которая вызывает `builtin compadd -A tmp "$@"` (собрать без добавления) и сохраняет: кандидатов, `-d` (отсюда описания, разделитель `--`), тэг/группу, `-P/-S/-p/-s/-q/-r/-f`, а также `PREFIX`, `IPREFIX`, `SUFFIX`, `ISUFFIX`, `compstate[quote]`. Затем `compstate[list]=''`, `compstate[insert]=''` — zsh ничего не выводит.

### 5.4. Асинхронный воркер

Completion-функции бывают медленными (git, docker, kubectl), поэтому не в основном шелле.

- В `precmd` через `zpty` форкается текущий zsh — воркер наследует функции, алиасы, `fpath`, `zstyle`, cwd. Убивается в `preexec`/`zshexit`. Если `$PWD` основного шелла изменился без команды (виджет с `cd`) — пересоздаётся.
- Внутри воркера крутится `vared`-цикл (completion-виджетам нужен активный ZLE): воркер подключается к демону, получает `REQ` (буфер, курсор), гоняет completion с перехватом, шлёт `CANDS` прямо в демон.
- Основной шелл шлёт демону только `CTX`; запросы воркеру шлёт демон. Вывод pty воркера основной шелл дренирует через `zle -F`.
- Отмена: у каждого запроса `gen`; устаревшие ответы отбрасываются. Пока воркер занят, новые запросы схлопываются в один. Висит дольше 500 мс — `SIGINT`, не помогло — пересоздание.
- Пока пользователь дописывает то же слово, демон фильтрует кэш сам, без воркера. Новый запрос — при смене слова/контекста, пересечении `/` или после 80 мс простоя.
- Риск: постоянный цикл в `vared` может не заработать. Тогда fallback — новый zpty на каждый запрос (так делает zsh-autocomplete). Проверяется первым делом.

### 5.5. Плагин

- Подключается последним в `.zshrc`, после oh-my-zsh. Клавиши перехватываются в первом `precmd` (чтобы видеть финальные биндинги всех плагинов).
- Для каждой клавиши сохраняется прежний виджет, биндится диспетчер: `меню видно ? действие ziro : прежний виджет`. Без `zle -K` (ломает vi-mode плагины).
- Хук `zle-line-pre-redraw`: буфер/курсор изменились → неблокирующе отправить `CTX`. Кадры от демона принимаются асинхронно через `zle -F` и применяются, если `gen` актуален.
- Навигация и принятие — локально: кадр содержит для каждой видимой строки готовые `new_buffer`/`new_cursor`. Демону шлётся `KEY` асинхронно (для прокрутки за окно).
- `zle-line-finish` стирает меню до выполнения команды. `preexec`/`precmd` шлют события истории (команда, cwd, время, код выхода, длительность).
- Предохранитель: не больше 32 неотвеченных запросов. EOF от демона → выключено до следующего `precmd`, там переподключение/автозапуск.
- Не активируется при `ZIRO_DISABLE=1`, внутри inshellisense (`ISTERM`) и на zsh < 5.8.

### 5.6. Демон

- Сокет `$XDG_RUNTIME_DIR/ziro/daemon.sock` (каталог 0700, сокет 0600, проверка uid через `SO_PEERCRED`), fallback `/tmp/ziro-$UID/`.
- Автозапуск из плагина: `ziro daemon --detach` (fork+setsid, `flock` против гонки шеллов).
- tokio current-thread. На сессию: последний контекст, кэш кандидатов, `gen`, размеры терминала.
- При несовпадении версии протокола плагин перезапускает демон.
- Цель по памяти: < 40 МБ при истории 100k. Лог: `$XDG_STATE_HOME/ziro/daemon.log`, уровень через `ZIRO_LOG`.
- Без включённого AI демон не открывает сетевых сокетов.

### 5.7. Протокол v1

Unix stream socket. Сообщение = поля через `\x1f`, конец — `\0`. Первое поле — тип. Буферы с `\0`/`\x1f`/`\x1e` не отправляются.

Шелл → демон:
- `HELLO␟v1␟<session>␟<pid>␟<tty>␟<TERM>␟<zsh_version>`
- `CTX␟<gen>␟<cursor>␟<cols>␟<lines>␟<keymap>␟<cwd>␟<flags>␟<buffer>` (`flags`: `h` — изменён навигацией по истории, `x` — явный вход в меню)
- `KEY␟<gen>␟<next|prev|accept|dismiss|page_up|page_down>`
- `HIST_START␟<id>␟<ts>␟<cwd>␟<cmd>`, `HIST_END␟<id>␟<exit>␟<duration_ms>`
- `TRACE␟<n>␟<us1>…` (тайминги плагина при `ZIRO_TRACE=1`)
- `BYE`

Воркер → демон:
- `WORKER_HELLO␟<session>␟<cwd>`
- `CANDS␟<gen>␟<prefix>␟<suffix>␟<iprefix>␟<isuffix>␟<quote>␟<n>`, затем `n` записей `C␟<group>␟<tag>␟<word>␟<display>␟<description>␟<flags>␟<-P>␟<-S>`, затем `END␟<gen>`

Демон → воркер: `REQ␟<gen>␟<cursor>␟<buffer>`

Демон → шелл:
- `CFG␟<arrows>␟<enter_accepts>␟<max_inflight>␟<keys…>` — ответ на `HELLO`
- `FRAME␟<gen>␟<ghost_len>␟<selected>␟<n_rows>␟<postdisplay>␟<n_hl>␟<hl…>`, затем на каждую видимую строку `<row_start>␟<row_end>␟<new_buffer>␟<new_cursor>`. `hl` = `start end style` в символах от начала `POSTDISPLAY`. `new_buffer` учитывает `-P/-S`, кавычки, `IPREFIX`.
- `CLEAR␟<gen>`, `ERR␟<code>␟<text>`

### 5.8. Ранжирование

1. Кандидаты compsys — основа. Группы в порядке compsys, внутри — нечёткий скор (точный префикс > начало слова > подпоследовательность), при равенстве — исходный порядок.
2. Буст по истории: аргумент, чаще использованный в этой позиции этой команды. Frecency: `Σ exp(-age/τ)`, τ = 7 дней, ×1.5 тот же cwd, ×0.3 ненулевой код выхода.
3. Целые строки истории (↺) — не больше 2, ниже compsys, если их скор не выше лучшего compsys более чем вдвое.
4. Ghost-text: лучшая строка истории с тем же префиксом (с учётом cwd), только когда курсор в конце.

### 5.9. Вставка

Заменяется `IPREFIX+PREFIX…SUFFIX+ISUFFIX` вокруг курсора на `IPREFIX + -P + quote(word) + -S + ISUFFIX`. Пробел в конце, если нет суффикса, это не каталог и нет `-q`/no-space. Экранирование как у compsys: внутри кавычек — только сама кавычка, без кавычек — backslash перед спецсимволами. Файлы с пробелами, кавычками, кириллицей должны вставляться корректно.

## 7. Бюджеты задержек

| Путь | p95 |
|---|---|
| Добавка ziro к обработке клавиши в zsh | ≤ 0.5 мс |
| Демон `CTX → FRAME` из кэша/истории | ≤ 2 мс |
| Нажатие → кадр, быстрый путь | ≤ 16 мс |
| Нажатие → кадр со свежими кандидатами compsys | ≤ 50 мс |
| Форк воркера | ≤ 5 мс |
| Эхо символа при зависшей completion-функции | без изменений |

Замер: `EPOCHREALTIME` в плагине при `ZIRO_TRACE=1` и `tracing`/гистограммы в демоне; `ziro stats` печатает p50/p95/p99.

## 8. Совместимость

- Терминалы: kitty, alacritty, foot, wezterm, терминал Zed, tmux — работает как обычный zsh.
- zsh ≥ 5.8 (5.9 рекомендовано, нужен для `memo=`).
- oh-my-zsh: `lib/key-bindings.zsh`, `lib/completion.zsh`, подсветчики синтаксиса (их `region_highlight` не трогаем, свои записи добавляем последними).
- fzf-tab: Tab без меню уходит к нему.
- zsh-autocomplete несовместим по смыслу — `ziro doctor` предупреждает.
- SSH: на удалённой машине нужен свой ziro.

## 9. Конфигурация

`~/.config/ziro/config.toml`, читает демон, перечитывает по `ziro reload`/SIGHUP. Все ключи необязательны.

```toml
[menu]
max_items = 8
min_prefix_first_word = 1
show_descriptions = true
border = "rounded"          # rounded | sharp | none
icons = "unicode"           # unicode | nerdfont | none
enter_accepts = "explicit"  # explicit | always | never

[ghost]
enable = true

[keys]                      # формат bindkey
accept = "^I"
arrows = "menu"             # menu | explicit
enter_menu = "^@"           # Ctrl+Space
next = ["^[[B", "^[OB"]
prev = ["^[[A", "^[OA", "^[[Z"]
dismiss = "^["

[worker]
timeout_ms = 500
refresh_idle_ms = 80

[history]
import_histfile = true
cwd_boost = 1.5
failed_penalty = 0.3

[theme]                     # синтаксис region_highlight
selected = "bg=4,fg=15"
match = "fg=3,bold"
description = "fg=8"
border = "fg=8"
ghost = "fg=8"
```

## 10. Этапы

- **MVP**: демон (история, ранжирование, раскладка), плагин (рендер, воркер, клавиши), ghost-text, совместимость с zsh-autosuggestions, CLI `ziro daemon | init zsh | doctor | stats`.
- **Потом**: systemd user unit, превью-панель, темы, AI, спеки withfig, atuin, статический musl-бинарь.
- **GUI-рендерер**: попап через Wayland `input-method-v2` (композитор ставит его у курсора любого терминала) или kitty graphics overlay. Демон отдаёт тот же кадр, меняется только отрисовка.

## 11. Критерии приёмки MVP

1. Сценарии 1–7 проходят вручную в kitty и в tmux внутри kitty.
2. Медленная completion-функция (`sleep 2`) не задерживает эхо; меню для неё появляется позже или молча не появляется.
3. С текущим `.zshrc` (git, оба подсветчика, zsh-autosuggestions): подсветка работает, ↑ на пустой строке и повторные ↑ — история, `echo *.md`+Tab раскрывает глоб, → принимает ghost-text, текст меню никогда не попадает в команду.
4. После Enter/Ctrl+C меню не остаётся, промпт не уезжает.
5. Имена файлов с пробелами, кавычками, кириллицей вставляются корректно.
6. Бюджеты §7 выполняются по `ziro stats`.
7. `cargo clippy --all-targets -- -D warnings` чистый, тесты зелёные.

## 12. Риски

- Постоянный `vared`-цикл в zpty — нетривиально (fallback в §5.4).
- Разбор описаний из `compadd -d` — эвристика, проверить на git/tar/ssh/docker/pacman.
- Зависимость от внутренних имён zsh-autosuggestions.
- Расхождение ширины символов между Rust и zsh.
